# 以单位为中心的一键巡检方案
**(设备档案化 · 全自动执行 · 彻底解放工程师 · 2026-11-13)**

> 大方向定案:工程师唯一的职责 = **把网络配通 + 录一次设备档案**;此后选单位、点一次"巡检本单位",登录、提权、下发命令、采集、判定、评分、出报告、归档全部自动完成。
> 本篇承接 v3 实施方案,新增"单位档案模型 / 批量导入 / 设备自动识别 / 执行引擎 / 数据全景"五个专项。

---

## 一、核心工作流(工程师视角,只有三步)

```
第 1 步(一次性,每单位 10~30 分钟)
  新建单位档案(名称/联系人/合同号/Logo)
  └─ 批量导入设备清单(Excel 模板粘贴:设备名/IP/用户名/一级密码/super密码/登录方式)
     或逐台录入;支持"自动识别"——只填 IP+账号密码,工具登录后自动判厂商/型号/版本

第 2 步(每次巡检,1 次点击)
  选单位 → 点「巡检本单位」 → 全自动(见第三节执行引擎)

第 3 步(收报告,0 操作)
  自动生成:正式版(甲方)+ 工程版 + Excel 台账 → 自动归档 output/单位/年月/ → (P2)自动邮件分发
```

**解放度对比**:现状工程师对每台设备手工登录+复制粘贴 2~4 小时/单位 → 目标 **3 分钟值守内完成一个单位**,失败设备自动标记原因(密码错/网络不通),补配后可单独补巡。

## 二、单位与设备档案模型(细化)

### 2.1 两级档案

**单位(客户)档案**(已有客户管理,补 3 字段):
| 字段 | 用途 |
|---|---|
| 名称/联系人/电话/备注 | 已有 |
| **合同编号** | 报告封面 |
| **Logo 文件**(可选) | 报告封面(A 版) |
| **甲方报告接收邮箱**(P2) | 自动分发 |

**设备档案**(挂在单位下,工程师只填 5+4 项):
| 分组 | 字段 | 说明 |
|---|---|---|
| **登录五要素**(工程师必填) | 登录地址(IP/域名)、**登录方式**(ssh/telnet/web/api/console)、**用户名**、**一级密码**(登录密码)、**super 密码**(可选) | 端口按方式自动给默认值(22/23/443),可改 |
| 自动识别(工具填) | 厂商、设备类型、型号、软件版本 | 见 2.2 |
| 巡检配置(默认即可) | 启用状态、超时、命令超时 | 一般不动 |
| 归属 | 单位、位置/机柜(可选) | 用于台账 |

### 2.2 设备自动识别(解放工程师的关键增强)

对标 eSight/NCE 自动发现纳管:工程师**只填 IP+账号密码** → 工具以通用方式登录(默认 SSH,失败自动降级试 Telnet)→ 执行 `display version` / `show version` / `show system information` → 按回显特征**自动判定厂商与设备类型**(回显含 "HUAWEI/Comware/H3C/Cisco IOS/JunOS/Ruijie" 等特征词 + 型号正则)→ 自动挂载对应驱动与只读命令表 → 回填档案。识别失败(未知厂商)时保留原始回显提示"待适配",不阻塞该单位其他设备。

### 2.3 批量建档(Excel 导入)

提供标准模板(单位/设备名/IP/登录方式/用户名/一级密码/super密码/备注),一次粘贴几十台;导入即做格式与连通性预检(不登录,仅 TCP 探测),问题行标红提示。**对标**:SolarWinds/网管平台批量发现导入的惯例。

### 2.4 档案密码保护(P1)

现状明文 YAML + 靠文件权限;升级为 **Windows DPAPI 绑定当前用户加密**(netmiko 凭据在内存解密,落盘始终密文)——单机工具的最优平衡(不需要主密码每次输入,拷到别的电脑/别的用户打不开)。对标堡垒机凭据保管。

## 三、单位巡检执行引擎(全自动时序)

```
「巡检本单位」点击后:
 0. 预检:逐台 TCP 探测(地址+端口)——不通者标记"网络未通",提示工程师配网
 1. 逐台(串行)自动登录:
    按档案 login_method 路由 → ssh / telnet(netmiko)| web / api(Playwright/requests)| console(串口/反向telnet,P2)
 2. 登录成功且档案有 super 密码 → 自动提权(super 命令,失败仅告警)
 3. 自动下发该设备类型的只读命令表(8~12 条,九大类)→ 收集原始回显
 4. 就地解析 + 规则判定(基础健康包 + 勾选的基线包)→ 健康评分(五类加权+critical 否决)
 5. 断开连接(异常也保证断开)
 6. 全部设备完成后:生成单位整体报告(模板 A/B/C 可勾选)→ 按编号归档 → (P2)邮件分发
```

**异常自治(不中断整单)**:
| 异常 | 自动处理 | 报告呈现 |
|---|---|---|
| 网络不通 | 跳过并在任务列表标记 | "网络未通,请配置网络后补巡" |
| 密码错 | 标记"档案密码待更新",继续下一台 | 单位报告异常清单列明 |
| 命令不支持/解析失败 | 该项记 UNKNOWN(保留原始回显) | UNKNOWN 项随回显进工程版,供离线适配 |
| 登录超时 | 自动重试 1 次 | 仍失败按网络不通处理 |

**只读双保险**:命令表全部为 display/show/GET 白名单(逐条评审入库);执行引擎加一道**正则白名单校验器**,任何非白名单动词(save/undo/delete/reboot/reset…)的命令在下发前直接拒绝并记录——从机制上杜绝误操作,写进产品承诺。

## 四、数据存储全景(输出数据去哪了)

| 数据 | 位置 | 生命周期 |
|---|---|---|
| 原始命令回显 | 工程版报告(证据区,已脱敏)+ 同名 .json | 随报告永久留存(甲乙各一份) |
| 结构化解析结果/评分 | `output/单位/年月/报告编号.json` | 随报告 |
| 配置快照(P1) | `output/configs/设备名/YYYYMMDD.txt` | 长期,供 diff 与审计 |
| 巡检历史(复查/趋势) | `data/patrol_history.db`(SQLite) | 长期,异常跟踪"连续期次"数据源 |
| 报告交付物 | `output/单位/年月/XJ-单位代码-YYYYMM-序号_{A|B|C}.{docx|xlsx|pdf}` | 交付后由双方自行归档 |
| Web 采集截图 | `output/screenshots/` | 随报告期次清理(默认保留 3 期) |

## 五、工程师 vs 工具 职责分工(最终形态)

| 环节 | 工程师 | 工具 |
|---|---|---|
| 网络可达 | ✅ 配通路由/防火墙策略 | TCP 预检并明示不通项 |
| 建档 | ✅ 首次录入五要素(可 Excel 批量) | 自动识别厂商/类型;密码加密保管 |
| 巡检执行 | ❌ | 逐台自动登录/提权/下发只读命令/采集/判定/评分 |
| 出报告 | ❌ | 三模板一键产出+编号归档 |
| 异常处理 | ✅ 仅处理"网络未通/密码待更新"标记项 | 自动隔离故障设备不阻塞整单 |
| 留存分发 | ❌(P2) | 自动归档+邮件双发 |
