# 巡检明细 · 登录方式 · 公司级报告 专项优化方案
**(对标国内外头部厂商 · 纯方案不含代码 · 2026-11-13)**

> 承接《巡检工具产品化方案.md》,本篇深化三个专题:
> ① 基础维护明细扩到头部厂商全景级;② 登录方式 ssh/telnet/web/console/api 全覆盖;③ 多设备一次巡检产出一份"公司级整体报告",提供 4 套报告模板。

## 一、巡检明细:对标头部厂商的全景清单

### 1.1 现状与差距

当前 42 条采集命令覆盖 8 类检查(信息/CPU/内存/接口/风扇/电源/日志/配置安全),对照华为 eSight/NCE、SolarWinds、Cisco、Juniper 健康检查实践,缺 8 个高价值维度:**温度、光模块 DDM、路由协议邻居、转发表规模、存储、配置一致性、重启原因、时间同步与日志外发**。

### 1.2 全景巡检明细体系(九大类,分级落地)

标注:★必选(头部厂商全有)/ ☆重要(头部厂商常见)/ ○按需(交换机/防火墙特有)

| 类别 | 巡检项(含判定标准) | 头部依据 | 命令示例(华为/H3C 系) |
|---|---|---|---|
| **1 基础信息** ★ | 厂商/型号/序列号/软件版本/**补丁版本**/**启动时长**/重启次数;**上次重启原因**(异常重启=高危) | 华为 NCE 设备档案;Juniper `show system uptime` | `display version` |
| **2 硬件环境** ★ | **温度**(所有传感器 Normal、无 Temp Warning);电源(状态+**冗余在线数**);风扇(状态+转速异常);**单板/子卡状态**(含 Absent 预期核对);**光模块 DDM**:收/发光功率、偏置电流、模块温度,对照厂商告警门限(Cisco DOM/华为 transceiver) | eSight 部件监控;Cisco DOM;Arista `show environment temperature` | `display device`、`display transceiver detail` |
| **3 资源** ★ | CPU(5s/1m/5m 三档,**>80% 告警**);内存(使用率+**最大可用块**碎片);**Flash/存储使用率**(日志写满会让设备宕机);进程 Top(可选) | 全厂商标配;S5700 实战清单 | `display cpu-usage`、`display memory-usage`、`dir` |
| **4 接口链路** ★ | Up/Down 清单(区分预期停用);**CRC/错包/丢包计数**(增量对比);**带宽利用率峰值**;协商速率/双工不匹配;STP 状态/**端口 error-disable**;**链路聚合成员状态** | SolarWinds 接口监控;Evernex 检查单 | `display interface`、`display link-aggregation verbose` |
| **5 二三层** ☆ | **MAC 表/ARP 表规模**(接近容量=隐患);路由表规模;**OSPF/BGP 邻居全 FULL**、邻居翻动;VRRP/堆叠/CSS/IRF 主备状态;默认路由存在性 | Juniper OSPF 验证;Auvik 邻居监控 | `display arp all`、`display ospf peer`、`display vrrp` |
| **6 安全合规** ☆ | Telnet 开关;SSH v2;SNMP 团体字(public/private=高危);**默认账号/空密码**;登录失败锁定;**NTP 同步状态**(时间漂移影响日志取証);**syslog 外发配置**(证据链);管理 ACL;空闲超时 | ManageEngine CIS 基线;等保 2.0 通用要求 | `display ntp-service status`、`display current-configuration` |
| **7 日志告警** ★ | severity≤3 日志条目与摘要;**崩溃记录 crashinfo**;**告警寄存器/黑盒**(华为) | 全厂商;Cisco `show logging` | `display logbuffer`、`display alarm all` |
| **8 配置管理** ★ | **running 与 startup 一致性(未保存配置=高危项,重启即丢)**;配置快照留存;**与上期配置 diff** | SolarWinds NCM/Oxidized 核心 | `compare configuration` |
| **9 设备特有** ○ | 防火墙:会话表规模/策略命中 Top/**攻击防护日志**/License 特性状态;无线 AC:AP 在线率/信道利用率;堆叠:成员/分裂检测 | 深信服 SAM;华为 WLAN 巡检 | `display firewall session table summary`、`display license` |

### 1.3 举一反三的三个设计原则(头部厂商共性)

1. **每项必有"判定标准+建议阈值"**,不是采了就行——规则引擎逐项给 PASS/FAIL/UNKNOWN 与整改建议(现有引擎直接支持,只加规则)。
2. **增量思维**:错包/接口计数、配置,都要"本期 vs 上期"对比才有诊断价值(报告呈现 diff 与增量)。
3. **证据链**:每项异常在报告中可下钻到原始命令回显(完整版报告已支持,保持)。

**落地工作量**:明细扩展按厂商逐个补命令+解析器,预计每厂商 0.5~1 天,建议先华为/H3C(现网量大),规则文件同步新增约 20 条。

## 二、登录方式矩阵:ssh / telnet / web / api / console

| 方式 | 定位 | 技术路径 | 头部对标 | 优先级 |
|---|---|---|---|---|
| **SSH** | 主通道(已支持 7 厂商) | netmiko(已有)+ super 提权(已有) | 全厂商标配 | ✅ 已有 |
| **Telnet** | 老设备/封闭内网 | netmiko `*_telnet` 设备类型(hp_comware_telnet 等),凭据与 SSH 共用,仅换 device_type 与端口 23 | eSight/SolarWinds 均支持 Telnet 接入 | **P0**(1 天:驱动表加 telnet 变体+端口默认 23) |
| **Web 页面** | 无 CLI 的防火墙/AC(已支持深信服/迪普) | Playwright(已有) | 深信服/山石 Web 控制台巡检 | ✅ 已有 |
| **API** | NGAF WebAPI 等(已支持) | requests+token(已有) | Fortinet RESTAPI、Meraki API | ✅ 已有 |
| **Console(串口)** | **带外应急通道**:设备失联/新开局/密码遗忘时的"最后入口" | pyserial 直连 COM 口(115200-8N1)+ 终端交互;采集命令集与 CLI 复用 | 齐治/JumpServer 堡垒机 console 代填;Opswise 带外管理 | **P2**(3 天:依赖工程师本机有串口线,场景特殊;UI 加"串口参数"配置) |

**登录方式选择逻辑**(对标堡垒机):设备档案里 login_method 单选 + 端口随之联动(telnet→23);巡检时按设备档案自动路由,一次任务中多设备可用不同方式混合登录——**这也是"多台设备一次巡检"的底层前提**。

## 三、公司级整体报告:多设备 → 一份报告

### 3.1 头部厂商怎么做

- **华为 iMaster NCE 云巡检**:按**租户/站点维度**出一份整体报告——全网健康评估+分设备明细+优化建议;
- **维保行业月报惯例**(乙方交付甲方):封面(双方+合同+周期)→ 网络概览 → 健康度汇总 → 异常与整改 → 设备明细 → 签字页;
- **BackBox**:一份报告自动分发两类读者(管理层精简版/工程师完整版)。

### 3.2 公司级报告文档结构(一次巡检 N 台设备 → 一份报告)

```
封面(甲方公司名+Logo位 · 乙方 · 合同号 · 巡检周期 · 报告编号)
一、巡检概述(范围:客户名下 N 台设备/巡检方式/巡检人/时间)
二、总体健康度(0-100 评分 + 全网达标率 + PASS/FAIL/UNKNOWN 分布图)
三、TOP 风险与整改建议(按严重级排序,每条含:设备/问题/依据/建议/期限)
四、上期问题复查(上期 FAIL 项本期状态——整改闭环,维保报告的灵魂)
五、按设备分组明细(每台:基本信息头 + 九大类检查结果表 + 原始回显)
附表A 设备资产台账(客户/型号/版本/IP/位置/序列号)
附表B 异常清单跟踪表(问题/责任方/状态/复测结果)
签字页(巡检人/审核人/甲方接收人 + 日期 + 双方盖章区)
```

### 3.3 四套报告模板(≥3 要求,给 4 套)

| 模板 | 读者 | 内容边界 | 格式 | 对标 |
|---|---|---|---|---|
| **A 正式汇报版** | 甲方领导/管理层 | 封面+概述+健康度+TOP 风险+建议+签字页;**无原始回显**;控制在 5~8 页 | Word/PDF | 华为 NCE 租户报告、维保月报 |
| **B 工程明细版** | 双方工程师 | A 的全部 + 逐设备九大类明细 + **完整原始回显**(证据链) | Word/PDF(可上百页)+HTML 在线翻 | BackBox 完整报告 |
| **C 台账表格版** | 甲方归档/审计 | 三个 Sheet:设备台账 / 检查结果矩阵 / 异常跟踪表 | **Excel** | 甲方台账惯例(SolarWinds 报表导出) |
| **D 变更对比版** | 变更评审/故障复盘 | 上期 vs 本期:配置 diff + 错包增量 + 新增告警 | Word/HTML | SolarWinds NCM 变更报告、Nautobot Golden Config |

**一次巡检、勾选模板、批量产出**——四套可任意组合(推荐默认组合 A+B+C)。

### 3.4 落地要点

1. 报告引擎已支持多设备合并(PatrolReport),新增的是**公司级封面/汇总/复查/签字页章节**与**模板分流渲染**;
2. "上期问题复查"依赖**报告历史库**(SQLite history 模块已在仓库待接入,正好启用);
3. Word 模板建议用 python-docx 模板文件(用户可自行改封面样式/换 Logo,不动代码)。

**工作量**:模板 A/B/C 约 3~4 天(含封面模板化),D 与 P1 配置 diff 合并实现约 2 天。
